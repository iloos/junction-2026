How it works

How Mandate is built

Every caller, whether the chef's screen, the in-app agent or your own agent, goes through one list of tools and the same checks, and only one function changes state.

The purchasing rules live in plain TypeScript with no I/O. Outside services sit behind ports, each with a fallback, so the demo keeps working when one is down. This page follows the code on the main branch.

When the agent may act alone

Every quoted line gets one of three outcomes. The same checks run for every caller, and a person decides everything the mandate doesn't allow.

Goes through alone

Only when every check passes:

  • Within the mandate's per-line, per-order and weekly capsCAP_EXCEEDED · tier.ts · eval s5
  • A product this kitchen already buysnew_sku · tier.ts
  • No allergen changeallergen_change · tier.ts · groups.test.ts
  • Valio states enough stockUNKNOWN_REQUIRED · validate.ts
  • A day the kitchen receives goodsoff_delivery_day · purchasing.test.ts
  • The exact terms (price, quantity, date) unchanged since the quoteTERMS_CHANGED · state.ts · eval s4
  • Before the ordering cut-offcutoff_passed · cutoff.test.ts
  • Whole packs of Valio's lot stepBELOW_LOT · eval s3

and nothing in the next column applies.

Held for a person

The line waits, with its reason on screen, when it has:

  • A cost over a cap, even when the order is splitCAP_EXCEEDED.weekly · tier.ts · eval s5
  • A product the kitchen hasn't bought beforenew_sku · tier.ts
  • An allergen change, decided apart from routine linesallergen_change · groups.test.ts
  • No stock figure from ValioUNKNOWN_REQUIRED · validate.ts
  • A delivery on a day the kitchen doesn't receive goodsoff_delivery_day · purchasing.test.ts
  • A substitute that breaks the kitchen's origin preferencesubstitute_breaks_preference · validate.ts
  • A product under a recall noticerecall · tier.ts
  • An outside agent's orderexternal_agent_needs_approval · tier.ts · eval s5
  • A model's caution. A model can add a caution that holds a line, never one that allows it.CAUTION.model_* · substitutes.ts

Refused

No approval passes it:

  • Over the hard limit, even split across linesover_hard_limit · ceiling.test.ts
  • After the ordering cut-offcutoff_passed · cutoff.test.ts · eval r5-f9
  • A part pack, off Valio's lot stepBELOW_LOT · eval s3
  • A product that breaks a stated requirement, such as lactose-freerequirement_unmet · purchasing.test.ts

A person approves, on the Kitchen screen, bound to the exact terms. Our agent and outside agents prepare, summarise and link the decision but never grant it: the chat refuses “approve it” and links to the approval in Kitchen, and the core refuses an approval granted by an outside agent. Any later edit voids the approval.

The three state machines

Plans, lines and approvals each move through a few fixed states; any edit voids the approval, and an order is committed once.

Each diagram scrolls sideways.

Plan

Green is the usual path. Any edit sends the plan back to draft and clears its terms hash, so an earlier approval no longer applies.

Line

A line inside the mandate is ordered without asking. Any other line waits for the chef with its reasons. A line below Valio's lot step can't be ordered at all.

Approval

An approval is tied to the plan version, the terms hash, the mandate version and an expiry. If any of them changes, the commit is refused.

Design choices

The rules that keep the agent honest are in code paths you can read and tests you can run.

Pure core, ports at the edgesrc/lib/core imports no Svelte, Node built-ins, vendor SDKs or server code. Lint enforces it.
One function changes stateapplyOps handles 9 op types. Each op is logged with a sequence number, its caller and the door it came through.
Approval is a hashtermsHash covers the delivery date and the sorted lines. If a price changes after approval, the hash differs and the commit is refused.
No lock across a network callValio, Gemini and web calls finish before the transaction starts. The lock covers only the checks and the write.
Every flow has a fixtureThe merge gate runs with LLM_PROVIDER=fixture: type check, lint, unit tests and evals through the real handlers on PGlite.
Fixed words“Supplier confirmed” is used only when a receipt backs it. Before that a line is planned, or ordered and awaiting the supplier.
