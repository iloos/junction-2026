How it works

How Mandate is built

Every caller, whether the chef's screen, the in-app agent or your own agent, goes through one list of tools and the same checks, and only one function changes state.

The purchasing rules live in plain TypeScript with no I/O. Outside services sit behind ports, each with a fallback, so the demo keeps working when one is down. This map follows the code on the main branch.

The system map

A call enters through a door, passes the same checks, is decided by the pure core and written to Postgres in one locked transaction, and the change goes back to every open screen.

Who may do what

Only the chef can approve. Agents, ours or yours, can read, plan and order inside the mandate, and a refused call is written to the log.

The caller's identity comes from its key or the signed visitor cookie, never from the request body. The scopes per caller are one table in the code, and the core refuses an approval from an outside agent even if a scope slipped.

The three state machines

Plans, lines and approvals each move through a few fixed states; any edit voids the approval, and an order is committed once.

Each diagram scrolls sideways.

Plan

Green is the usual path. Any edit sends the plan back to draft and clears its terms hash, so an earlier approval no longer applies.

Line

A line inside the mandate is ordered without asking. Any other line waits for the chef with its reasons. A line below Valio's lot step can't be ordered at all.

Approval

An approval is tied to the plan version, the terms hash, the mandate version and an expiry. If any of them changes, the commit is refused.

Design choices

The rules that keep the agent honest are in code paths you can read and tests you can run.

Pure core, ports at the edgesrc/lib/core imports no Svelte, Node built-ins, vendor SDKs or server code. Lint enforces it.
One function changes stateapplyOps handles 9 op types. Each op is logged with a sequence number, its caller and the door it came through.
Approval is a hashtermsHash covers the delivery date and the sorted lines. If a price changes after approval, the hash differs and the commit is refused.
No lock across a network callValio, Gemini and web calls finish before the transaction starts. The lock covers only the checks and the write.
Every flow has a fixtureThe merge gate runs with LLM_PROVIDER=fixture: type check, lint, unit tests and evals through the real handlers on PGlite.
Fixed words“Supplier confirmed” is used only when a receipt backs it. Before that a line is planned, or ordered and awaiting the supplier.
