# Ring 2 review: UI/UX and visualisation (ring1-clean, PGlite fixture, Playwright 1440 and 390)

_Condensed by the lead. Screenshots: `scratch/uxreview/` in the main checkout (gitignored); walk scripts `walk2.mjs d|m`, `walk5.mjs`, `wall.mjs` there are the "done means seen" re-check._

## Per screen
- **Kitchen /**: the engine is all visible (formula per dish, unit bases, ruler, rescue table, Why drawer = best thing in the app; approval per reason group, receipt, retry). Problems: flat hierarchy (first dish at y≈700; "By when" chart with 2 bars); page 3,444 px desktop / 7,919 px phone with approval at the bottom; the same thing counted three ways (header lines vs panel decisions vs sticky bar); state chips mix policy tiers, availability and execution; rescue noise ("fit 2/4 · rule estimate" on every row, score labels on bars, rank order looks wrong without "supply tier first"); make-in-house reads as 5 separate products; after commit editing stays live and the button looks broken, no "ordered, awaiting supplier" frame; dev jargon (`ws-demo · run-1`, simulated clock, idempotency key); 13 arbitrary text sizes; mobile chart labels collide and post-commit page scrolls sideways.
- **Request /request**: cleanest screen; Lookup card is the "system underneath" in plain words. Problems: step icons stay amber after approval; raw approver id; raw unit codes (ST, KI); ISO date as a warning; **event path dead-ends** at "Menu proposal: next"; milk stepper doesn't fit events.
- **Ops /ops**: a separate visual system (own hex palette, 18 px base); **stale data**: rescued outages still red "Cannot order" cases after commit (per-line not per-cause); wallboard 180 px card per line; duplicated events; trace drawer shows raw JSON, enum names, raw ids, empty by default; **mobile broken** (481 px wide, overlaps).
- **Agents /agents**: clear and honest; missing client config snippet, "your calls" feed, held order → approval link; third style dialect (Tailwind defaults).

## Personas
Chef can finish (~6 clicks) but the page never says "2 decisions before Tue 17:00", strategies look like products, nothing reframes after commit, phone approval is 8 screens down; make "replaced X because Y" a visible caption. Purchaser: needs unit words, green steps, handoff "this order is now in your Kitchen plan"; events stall. Approver: no surface; needs one decision card (what, exact terms, why, consequence of decline, by when, the terms hash as a seal, why a named approver). Ops: can't trust counts; needs cases per cause closed by rescue/commit, who acts by when, deep link as primary action. Agent dev: needs client config, live "your calls", approval URL with state.

## IA
Primary object = **procurement task** with its plan version. Global shell: product, kitchen switcher, tasks inbox ("2 decisions need you"), **System** toggle; workspace/run/clock into a small Sandbox menu; scenario labels into one "Demo data ⓘ" pill. Task page zones: **Decide** (decision cards + "needs you by when"; phone default) · **Plan** (dishes → needs → lines, compact rows with ruler, expand for formula/rescue/Why) · **Order** (receipt, supplier confirmed vs awaiting, retry). Request becomes the "New request" composer docked on Kitchen; its result is a task. **Chat** = right dock (bottom sheet on phone) scoped to the open task/selection; each turn ends with a computed outcome line and live cards by id; never approves; op log is the record. "Show the system": plain words by default; **System layer** toggle overlays formula, funnel, gate, hash seal, op ids (on for judges via `?system=1`); **Ops is the explainer** (per-cause cases, op-log timeline, agent run graph; trace drawer → page with Run graph · Calls · Raw); /agents shows the same run graph filtered by your key.

## Visual system
One token set, two themes (Ops = `[data-theme=dark]` of the same oklch tokens). Type scale: display 28/32 · title 20/26 · heading 15/20 semibold · body 14/20 · meta 12.5/16 · micro 11/14 caps; Ops +4 px; `@theme --text-*`, ban `text-[..px]` in the gate. Supply states (D10), colour + pattern + word: supplier confirmed (solid deep green) · ordered, awaiting supplier (green outline + hatch) · planned known stock (teal solid) · planned unknown stock (amber hatch) · unresolved (red outline, empty) · forbidden (red solid ⊘) · excess (grey tick hatch past the need mark). Authorization is a separate axis (shape/icon): within mandate · needs your approval · needs named approver (shield) · approved · forbidden. Execution a small mono tag. 44 px rows desktop, 56 px cards phone, mono right-aligned numbers, one primary action per zone. Shared components in `src/lib/ui/`: TaskHeader, DecisionCard, LineRow, StrategyCard (AND group), RescueCompare, CoverageRuler, Receipt, OpEvent, SourceChip, LabelPill.
