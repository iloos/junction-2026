How Mandate is built

This map follows the code on main. Every caller, person or agent, goes through one list of tools and the same handler steps. The rules live in plain TypeScript with no I/O. Outside services sit behind ports, each with a fallback.

The three state machines

Plans, lines and approvals each move through a few fixed states. An edit voids the approval, and an order is committed once.

Plan

Green is the usual path. Any edit sends the plan back to draft and clears the terms hash, so an earlier approval no longer applies.

Line

A line inside the mandate is ordered without asking. Any other line is held for a person with its reasons. Stock Valio has not stated is never counted as cover.

Approval

An approval is tied to the plan version, the terms hash, the mandate version and an expiry. If any of them changes, the commit is refused.

Design choices

Pure core, ports at the edgesrc/lib/core has no Svelte, no DOM, no SDK. Lint enforces it.
One function changes stateapplyOps handles 8 op types. Each op is versioned and logged with its actor and door.
Approval is a hashtermsHash(deliverBy + sorted lines). If a price changes after approval, the hash differs and the commit is refused.
Never hold a lock across a modelValio and Gemini calls finish before the transaction starts. The lock covers only the write.
Every flow has a fixtureThe merge gate runs with LLM_PROVIDER=fixture: about 420 tests and evals through the real handlers.
Fixed wordingThe UI says “supplier confirmed” only when a receipt backs it. Tests check the wording against VOCABULARY.md.
