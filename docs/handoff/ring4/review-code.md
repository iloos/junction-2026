# Ring 4 review: code since the Ring 3 review

_Independent reviewer, Sat 14 Nov night, main at `6af9c1b`, scope `git diff 5b0fabb..HEAD` (200 commits, 286 files, +21k). Read-only. `pnpm check`: 0 errors, 0 warnings (6236 files)._

## Verdict
1. **The trust core still holds, and it got stronger.** New since Ring 3: a run fence under the workspace lock (`store/drizzle-store.ts:333-345`, refuses a write on a stale run and any op whose run/workspace strays), `onCurrentRun` on every `serveTool` call (`tools/serve.ts:96`), per-key call windows for outside agents (`tools/key-limits.ts`), refusals in the op log (`tools/refusals.ts`), server-owned order keys in the agent loop (`agent/loop.ts:289-312`), one task-id helper (`contracts/task.ts:164-173`), one core next-action rule (`core/mandate/next.ts`), and chat routes on the wrapped handlers inside `withCallScope` (`api/chat/turn/+server.ts:54,89`).
2. **D13 holds in code:** the dock approves only through `KitchenStore.approve` → `/kitchen-api/tool` → `callTool` (bound to the rendered run/plan/version, `kitchen/live.ts:137-148`) as the chef. Chat turns act as `principalContext` (chef ∩ agent scopes, `chat/turn.ts:511-520`); no server chat/agent path calls `approve`. The calendar token is read-only and HMAC-separated (`demo/visitor-id.ts:58-75`). `read_image` validates type from bytes, size and base64 and never persists the picture.
3. **What regressed is the seams again:** due times computed three ways, op→sentence tables four times, product names and money formatted ad hoc, and a dock/page server-session coupling that can flip the Kitchen page to another plan (inferred, M1).
4. **Ring 3's cleanup batch did not land:** stub fallback, lane comments, substring approve guard, M7, L2, L3 are all still there.

## Findings (ranked)

### High
None found that breaks a guarantee. The highest risks are M1 (demo path) and M2 (deploy surface).

### Medium
**M1. The dock's second KitchenStore moves the server session, so the Kitchen page can switch plans under the chef.** _Inferred from code; verify with a two-store test._ The dock loads its decision's plan with `st.load(id)` (`ui/chat/ChatDock.svelte:164-171`) → `focusPlan` sets `s.planId`/`s.kitchenId` on the browser's one session (`kitchen/live.ts:261-265`). `callTool` also adopts whatever plan the caller names (`live.ts:119-127`). The page's store reads with `snapshot(mode, focusedPlan ?? undefined)` (`kitchen.svelte.ts:294,379`); `focusedPlan` is null on a normal page load, so its next refresh returns the dock's plan (`findPlan`, `live.ts:154-160`). The D13 path ("approve the butter order in the dock while the page shows the event") is exactly this. **Fix:** the page store sets `focusedPlan = snap.plan.id` after its first snapshot, or `snapshot()` without a plan ignores a plan adopted by another store (keep a per-store id). Extend `evals/ui/dock-approve.e2e.ts` to assert the page still shows its own plan after a dock approve. **Size:** S. **Owner:** 1f.

**M2. `BODY_SIZE_LIMIT=8M` applies to every route, and MCP parses every POST body twice.** _Verified._ `Dockerfile:14` raises the limit app-wide for one tool. `createMcpEndpoint` clones and JSON-parses every POST for `gateUnlisted` (`tools/mcp.ts:160,177-191`) before the SDK parses it again. Chat/request/menu routes read bodies before any rate limit. **Fix:** keep 8M, but reject `content-length > 64 kB` in `hooks.server.ts` for every path except `/api/tools/read_image` and `/mcp*`; in `gateUnlisted` skip bodies over 64 kB (a refusal probe is small). **Size:** S. **Owner:** 9c.

**M3. Due times are computed three ways.** _Verified._ `ui/decisions.ts:137-151` `decisionsDue` = min(approval expiry, view validUntil, open-line closingTime), fallback `SCENARIO.cutoff`. `core/mandate/next.ts:76-79` `deadline` = closingTime of act-now lines only. `routes/ops/problems.ts:203-219,271-282,317,341` = closingTime else `SCENARIO.cutoff`. An approval expiring before the cut-off makes the DecisionCard (and the calendar, `server/calendar.ts:52`) say one time and chat/MCP ("approve before …") another. **Fix:** one `dueOf(plan, approval, lines?)` in `core/mandate/` (move `decisionsDue` there); `next.ts` and `problems.ts` call it. **Size:** S. **Owner:** 8d.

**M4. Web routes still run tools outside `serveTool` (Ring 3 M3, open).** _Verified._ `api/web/recall/+server.ts:24-55` (and facts/outside) call `webTools(env)` with `authed()`: no `onCurrentRun`, no key windows, no output validation; `{url}` ingests and writes `RecordAnomaly` ops for any key kind, including read-only `job`. The run fence now turns a stale run into a 409 rather than a wrong-run write, which is safer but still a failure. **Fix:** route `productId`/facts/outside through `serveTool`; gate URL ingest on the `plan` scope. **Size:** M. **Owner:** D.

**M5. Menu grounding is cached by dish name across all visitors, but its verdict depends on the model's ingredients.** _Verified._ `web/grounding.ts:165-167,189-192` keys the process map by `slug(dishName)`, and `groundDish` compares that proposal's ingredient list to the recipes (`:115-161`). A second visitor's "Lanttulaatikko" with different ingredients shows the first visitor's "Matches 2 sourced recipes". A `failed` entry sticks for every visitor until restart. It also runs detached with no trace (`:223`, rule 7). **Fix:** key by `slug(name) + digest(ingredients)`; pass a bus trace for the visitor. **Size:** S. **Owner:** D.

**M6. Op → sentence wording exists four times.** _Verified._ `routes/agents/+page.server.ts:118-170` (`opWords`), `routes/ops/labels.ts:95+`, `routes/ops/story.ts:150+` and `routes/ops/OpTimeline.svelte:65` each switch on `op.type`. Money is formatted three ways (`ui/format.ts:4`, `ops/labels.ts:14-17` en-IE, `agents/+page.server.ts:107-108` en-GB), plus a private `day()` with a hard-coded `Europe/Helsinki` (`agents/+page.server.ts:110-116`) beside `SCENARIO.timeZone`. **Fix (post-freeze, or when one of them is touched):** one `opSentence(op, names)` in `ui/`, `money` and `day` from `ui/format`. **Size:** M. **Owner:** 9c.

### Low

Core and services use `nameFi` (`core/services/contention.ts:121`, `substitutes.ts:293`, `events.ts:430`), `/ops/views` uses `nameEn || nameFi` (`ops/views/+server.ts:44`), Ops falls back to `Product <id>` (`ops/labels.ts:68`).
