# Fixtures

Small, hand-checked or generated data that tests, evals, the offline demo and the fixture adapters read. The full Valio datasets stay in `data/valio/` (gitignored) and are never committed here.

## seeds/ (hand-written; every number is a team estimate unless its provenance says otherwise)
| File | What | Read by |
|---|---|---|
| `kitchens.json` | Three fictional kitchens: `k-hotel`, `k-lounas`, `k-central`. Weights, origin rules, mandate caps (team estimates chosen so the scenarios exercise each cap), factor sensitivity | `server/store/db-ports.ts` (seeds each workspace), evals, contract tests |
| `christmas-buffet-140.json` | `event-xmas-140`: joulupöytä for 140 guests at `k-hotel` on 12 Dec 2026, 13 dishes with g served per guest and yields, prices from the Valio mock (14 Nov). Its **`rescue`** section is the hand-checked preflight: whole ham 462490 → HK Palvikinkku 476768 (Stock); lanttulaatikko 462482 and joulutorttu 473317 → make in house from Stock ingredients (`per` amounts resize with the need). Terminal options stay unknown and never count as cover | `server/store/db-ports.ts`, `core/demand/event.ts`, `core/services/{events,substitutes}.ts`, the Kitchen fixture, evals |
| `calendar-factors.json` | Demand factors with a source each (holidays, closures as a mask), clamp [0.5, 2]; `kind: estimate` must be labelled "team estimate" in the Why drawer | `core/demand` |

Change a seed only with its consumers' tests green (`pnpm gate`); `src/lib/core/contracts/seeds.test.ts` parses the kitchens against the `Kitchen` contract and checks eval reason codes.

## views/ (generated: do not hand-edit)
Real tool outputs (a `Plan` with `view: PlanView` and `lines[].view: LineView`) so UI and agent code can build against what the server returns.

| File | Generated by |
|---|---|
| `christmas-rescued.json` | `src/lib/server/store/views-fixture.test.ts`: the Christmas plan after the rescues |
| `milk-direct.json` | `src/lib/server/store/direct.test.ts`: `place_order` 10 L lactose-free milk as a direct need |

Regenerate both (PGlite, fixture catalogue, no network):

```sh
WRITE_VIEW_FIXTURES=1 pnpm vitest run --project server src/lib/server/store/views-fixture.test.ts src/lib/server/store/direct.test.ts
```

In PowerShell: `$env:WRITE_VIEW_FIXTURES=1; pnpm vitest run --project server src/lib/server/store/views-fixture.test.ts src/lib/server/store/direct.test.ts`. Commit the regenerated files with the change that altered the view.
